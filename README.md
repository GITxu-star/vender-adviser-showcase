# 地摊顾问（Vendor Advisor）

> 给摆摊老板用的 AI 经营顾问：填一次问卷，走完 7 步，拿到「今晚就能做」的一个动作，第二天回来报效果，形成一轮完整闭环。
>
> **本仓库为参赛展示版**：完整案例库、RAG 知识库与知识图谱数据不随仓库分发，仅保留代码、开发思路与推理实现，详见文末「关于本展示版」。

- **线上 Demo**：http://124.222.236.27:8080
- **访问码**：随报名材料提供（防止 API 额度被刷）
- 建议用手机浏览器打开体验，桌面端也可用

---

## 一、解决什么问题

摆摊老板最常遇到的困境不是「不知道要努力」，而是：

1. 站在摊前看不出自己哪里有问题（东西摆得对不对、价格标没标、灯光够不够）
2. 网上的经营建议都是给门店的，动辄「做活动、上团购、搞装修」，摊主执行不了
3. 听了一堆建议，不知道先做哪一件，做完也不知道有没有用

本产品把「诊断 → 给一个动作 → 执行 → 复盘」压到 7 屏、5 分钟内完成，且所有建议都约束在「今晚 2 小时内能做完、成本几十元以内、有退路」。

## 二、7 屏流程

| 屏 | 名称 | 用户做什么 | 系统做什么 |
|---|---|---|---|
| 1 | 摊位问卷 | 填卖什么、在哪卖、价格、每天卖多少、摊位是否固定、时段 | 识别品类、计算基准指标 |
| 2 | 顾客反应 | 选顾客是走过去还是停下来、看哪里 | 判断「拦客能力」与视觉问题 |
| 3 | 问题诊断 | 阅读诊断卡 | 给出核心矛盾与依据，不堆砌结论 |
| 4 | 行动方案 | 从 3 个方向里挑一个 | 多方向候选 + 打分 + 融合，输出具体动作、成本、退路 |
| 5 | 指标变化 | 看天气/竞争/时段对自己的影响 | 按品类、场地、时段真实计算，非固定模板 |
| 6 | 执行清单 | 照着做 | 拆成可勾选的执行项，配等距示意图 |
| 7 | 效果复盘 | 选「明显好 / 有点 / 没变化 / 更差」 | 只针对所选效果下结论，并开下一轮 |

交互要点：

- **AI 不是自动弹的**，由用户点「AI 诊断」触发（移动端底部条右侧按钮），避免用户被打断
- 每一屏的 AI 回复都由大模型生成，且带上当前屏上下文、用户原话和历史提问；同一问题重复点不会得到同一句套话
- 移动端：底部常驻输入条 + 半屏对话抽屉，问卷和对话可同时可见
- PC 端：右侧常驻 AI 面板，宽度足够时不遮挡表单

## 三、技术架构

```
前端 (React + Vite + TS)
  ├─ 7 屏页面（Screen1~7）+ Zustand persist 本地状态
  ├─ AI 面板 / 移动端底部条 + 半屏 Sheet
  ├─ 等距摊位示意图（Canvas 2D）+ 顾客动线（Three.js）
  └─ localStorage 历史记录（每轮存档，可展开/删除/清空）
              │  HTTP  /api/*
              ▼
后端 (FastAPI)
  ├─ /api/process   问卷 → 各屏卡片内容（规则 + 品类识别）
  ├─ /api/chat      RAG 主链路 + 大模型回复
  ├─ /api/visualize 摊位示意图数据
  ├─ /api/verify    访问码校验
  ├─ /api/feedback  用户反馈收集
  └─ 访问码中间件（X-Access-Code）
              │
              ├─ DeepSeek（deepseek-chat）：诊断、方案、复盘文本
              ├─ 硅基流动 BAAI/bge-m3（1024 维）：检索向量化
              └─ SQLite 向量库：案例知识检索
```

### RAG 链路

```
用户提问
  → Query Rewrite（口语/错别字 → 干净检索句）
  → Multi-Query 展开（视觉 / 价格 / 体验 / 差异化等多角度）
  → 向量检索 top-k（bge-m3 + cosine）
  → 规则 Reranker（成本、耗时、记忆度、上下文适配度等维度打分）
  → RRF 融合 + 候选去重（相似度 > 0.85 淘汰）
  → 结合问卷上下文生成最终回复
```

知识库为 13 个真实摊位案例（烤红薯、冰糖雪梨、坚果、活鱼、蔬菜、书籍、衬衫等），每个案例含「改了哪四件事 / 结果数字 / 成本与退路 / 避坑点」。

### 关键工程细节

- **向量维度一致性**：建库与查询统一 1024 维 bge-m3，建库使用严格模式，Embedding 调用失败直接报错，避免静默写入无语义哈希向量导致「检索永远为空」
- **缓存键含用户提问**：同一屏不同问题不会命中同一缓存
- **访问码中间件**：401 返回 JSONResponse，注册顺序在 CORS 之后，保证跨域下错误可读

## 五、本地运行

前置：Node 20+、Python 3.11+

```bash
# 1. 后端
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env        # 填入 DEEPSEEK_API_KEY / SILICONFLOW_API_KEY
python rebuild_db.py        # 构建向量库（首次必做）
uvicorn main:app --reload --port 8000

# 2. 前端（另开终端）
npm ci
npm run dev                 # 默认 http://localhost:5173
```

前端默认请求 `/api`，本地开发时在 `.env.local` 指定后端地址：

```
VITE_API_BASE=http://localhost:8000/api
```

## 六、部署

单容器同源部署：Node 阶段构建 `dist`，Python 阶段由 FastAPI 托管静态文件，无需 Nginx 与跨域配置。

```bash
docker compose up -d --build
```

服务器上 `.env` 保存密钥（不入库、不入镜像），向量库与反馈文件通过命名卷持久化。

## 七、隐私与合规

- 问卷、诊断、方案、对话与历史记录**只存在用户本机浏览器**（localStorage），不上传云端保存
- 用户点「AI 诊断」时，问卷与最近对话会发送至本服务并转给大模型（DeepSeek）推理；检索时问题文本会发给向量化服务（硅基流动）；服务器不建会话数据库
- 用户主动提交的「反馈」内容保存在服务器，用于改进产品，不包含问卷与对话
- 不采集通讯录、位置、相册等与功能无关的信息，不出售、不共享数据
- 应用内「请阅读应用说明与用户隐私说明」入口向用户完整披露以上内容

## 八、已知局限

- 建议来自大模型与案例库，不保证一定提升营业额；涉及城管、食品安全、经营许可等以当地规定为准
- 历史记录仅存本机，换设备或清缓存会丢失
- 知识库目前以中小城市夜市/早市摊位为主，跨行业覆盖仍在扩充
- 反馈数据目前以文件形式沉淀，尚未做可视化后台

## 十、关于本展示版

本仓库是参赛展示用的代码版本，用于说明产品思路与工程实现，**不包含**以下数据资产：

| 未包含内容 | 位置 | 说明 |
|---|---|---|
| 真实摊位案例库 | `backend/knowledge/案例库/` | 作者实地整理并脱敏的 20 个案例，含四件事改动、结果数字、成本与退路 |
| RAG 知识库 | `backend/knowledge/百科/`、`法规/` | 经营常识、点位流量、政策规定等切块语料 |
| 知识图谱数据 | `backend/data/rules.json` | 符号规则库（品类×时段策略、困境→根因、竞争约束等）与运行时统计 |
| 向量索引 | `backend/data/vector.db` | bge-m3 1024 维索引 |

因此直接克隆本仓库后，RAG 检索没有语料、`rebuild_db.py` 无法建库，页面会退化为规则 + 大模型回答。这是预期行为，不是缺文件。

知识图谱的**规则结构与推理代码**是完整公开的（`backend/rules.py` 中的 `Rule` / `RuleGraph` / 冲突消解 / 品类适配），只是具体案例语料不公开。
